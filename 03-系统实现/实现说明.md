# 系统实现说明

按 `02-数据模型/` 建好集合以后，我做了一个能跑起来的演示系统，用来检验模型能不能支撑需求里的业务。完整代码在 `源码/adc-demo/`。

## 患者端小程序

微信原生框架，12 个页面，自定义 tabBar 是「首页 / 预约 / 我的预约 / 我的」四项。首页看下次预约和门店，预约页选门店、日期、牙医、时段后提交，我的预约页按状态筛选并自助取消或改约，就诊记录页看每次的治疗明细和合计，结算单页看金额、单价快照和单号。另外有档案、登录、隐私须知、门店、牙医、关于几个页面。

请求统一走 `utils/api.js`，云函数调用有超时和一次重试。页面只读云端，连不上时明确提示并给重连入口，不用本地假数据顶替。

## 员工端网页

一个静态页面，CSS、SDK 和业务 JS 都内联在同一个 html 里，放到静态托管上就能打开。按需求文档里的岗位分了 5 个角色：前台、牙医、财务、运营、总部经理，各自能看到的菜单不一样，共 13 个视图（今日看板、预约管理、患者档案、诊间治疗、结算开单、成本与费用、季度报表、门店与牙医、诊疗项目、出诊排班、操作记录、核算审批、员工账号）。

登录走云函数的 `staff.login`，密码用 scrypt 存哈希，签发 8 小时 token。员工端接口统一标记 STAFF_ONLY，服务端按角色判权限，页面上的写按钮也按角色隐藏，前后端各做了一重限制。

## 后端

CloudBase 环境里四个云函数：`api` 是唯一业务入口，按 action 分发；`initData` 灌演示数据；`seedStaff` 初始化员工账号；`seedSchedules` 生成出诊排班。小程序和网页都调 `api`，读写同一套集合，没有为网页单独建表，也没有同步任务，所以一边写入另一边立刻能看到。

`api` 里按业务分了组：字典和元数据，患者端的演示身份、预约、取消、改约、记录、结算，员工端的登录、到诊登记、诊间录入、开单、成本、季度报表，一共 59 个 action（原有 46 个，补排班、操作记录、核算审批、员工账号时新增 13 个）。患者端每个接口都校验 OPENID 归属。

演示数据是 2 家门店、3 位牙医、7 个诊疗项目、4 位患者，另有若干历史预约和结算单。

## 做的时候遇到的几个问题

新开的云环境没有文档数据库实例，调用 `wx.cloud.database()` 直接报资源不存在，换套餐也没用，后来开了 pgdoc 插件、由 PostgreSQL 承载文档 API 才通。

云函数默认超时只有 3 秒，灌演示数据要顺序写几十条记录，每次都半路被掐断。把超时调到 60 秒以后正常了。

给预约时段建了唯一索引以后，发现取消预约会把那个时段永久锁死，别人再也约不上。改成取消时把 `slot_key` 写成释放态，索引还留着，但不再占用原键。

网页放在后台一段时间再切回来，登录态过期，第一次请求会被网关拒掉。后来改成每次进页面重新签票，不做本地登录态短路；断线后下一次操作会自己重连，读取偶发失败也会先自动重试一次，不用刷新页面。

## 和原需求的差别

需求文档里患者是通过电话和柜台办理、没有自助端的，主体业务都在员工端。我把患者查询这一部分单独做成了小程序，方便演示跨店资料和一就诊一单这些规则，属于对原需求的延伸；员工端的岗位分工和用例顺序没有改。

# 运行与访问

## 本地跑起来

小程序：用微信开发者工具导入 `源码/adc-demo/`，AppID 写在 `project.config.json` 里。页面只读云端，云环境不可用时直接提示连接失败，不会显示本地假数据。

员工端网页：在 `源码/adc-demo/` 下执行 `node web/serve.js`，浏览器打开终端提示的地址。页面连的是云端，读到的就是小程序里那份数据。

## 账号

网页的身份按钮背后是云端预置的 8 个员工账号，点哪个就用哪个账号签票，密码由页面自动带上，不用手输。密码在云函数里以 scrypt 哈希保存和比对，不写进仓库文档。

| 场景 | 说明 |
|---|---|
| 网页身份入口 | 点选即登录，无需输入账号密码 |
| 员工账号 | 8 个，见下方清单；密码由 `seedStaff` 初始化 |
| `seedStaff` 执行锁 | 初始化时一次性使用，由部署者本地传入 |

浏览器要能调云函数，先得有一个 CloudBase 会话，页面内部用一个界面上看不到的通道账号签票。它不是员工账号，没有任何角色，读不到业务数据。

8 个账号分 5 个角色：前台 `desk`（周晓雯·天河店）、`desk2`（何嘉·越秀店），牙医 `dentist`（陈安）、`dentist2`（李敏）、`dentist3`（王强），财务 `finance`（许静），运营 `ops`（梁俊），总部经理 `manager`（黄立群）。同一个牙医账号只能看本人的排班和诊间，要换医生就点右上角「切换账号」。

小程序端不用账号密码，打开后从 4 个虚构档案（林小雅 / 张家明 / 陈慧 / 黄志远）里选一个就能进，随时可切换。v1.2.0 起不收集姓名和手机号。

## 网页

- 进去点一个身份（前台 / 牙医 / 财务 / 运营 / 总部经理），不填账号密码，直接进对应的视图。
- 页面上的数据全部来自云端，和小程序是同一份；在网页里改状态、录治疗、开单，小程序那边马上能看到。
- 微信里打开如果提示非官方网页，点右上角「…」→「在浏览器打开」。

网页是员工端，5 个角色 13 个视图；小程序是患者端，两端分工不同。

## 测试脚本

在 `源码/adc-demo/` 下用 Node 跑，例如：

    node tests/mp-lint.js        # 小程序页面文件、JSON、跳转路径
    node tests/mp-flow.js        # 患者端流程
    node tests/mp-confirm.js     # 二次确认
    node tests/smoke.js          # 云函数业务规则（内存桩）
    node tests/enhance.js        # 排班 / 留痕 / 核算审批 / 员工账号
    node tests/web-dom.js        # 网页静态结构：视图容器、内联构建是否最新
    node tests/web-flow.js       # 网页 13 个视图与角色菜单
    node tests/web-login.js      # 网页身份登录
    node tests/web-cloud-recover.js  # 断网与重连
    node tests/web-selftest.js   # 单文件完整性

大部分脚本不需要联网。`web-cloud-diag.js` 和 `e2e-cloud.js` 要连云端，其中 `e2e-cloud.js` 会往演示数据里写记录，手动跑之前先看一下。
